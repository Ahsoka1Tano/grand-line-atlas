# Локальная альфа 0.2 — игровое ядро

Дата: 8 октября 2026. Первый рабочий этап после визуальных прототипов.

## Поведение

При первом посещении создаётся локальный профиль капитана: пять привязанных стартовых экземпляров Луффи, Зоро, Нами, Усоппа и Санджи; 1000 Berries; один подарочный бокс; пять участников экипажа и три выбранных боевых карточки.

Открытие выдаёт три случайные карты из каталога 12 изданий. Первый бокс бесплатный, последующие стоят 250 Berries. Вероятности каждой карточки: C 60%, R 28%, SR 10%, SSR 2%. Выбор внутри редкости равновероятный; гарантированного редкого слота и накопительной гарантии пока нет.

Карты сохраняются до начала визуального раскрытия. Закрытие анимации не отменяет выдачу. История показывает 20 последних открытий и позволяет пересмотреть их без нового списания.

Коллекция разделена на полученные карты и общий каталог. Избранное сохраняется на сервере и доступно только для полученных изданий. Дубли имеют отдельные идентификаторы, хотя интерфейс группирует их по изданиям.

Экипаж содержит от трёх до пяти разных персонажей, из которых ровно три выбраны для будущих боёв. Карточки можно менять, переставлять и убирать. При выборе уже занятого персонажа UI меняет участников местами. Сервер проверяет владение, отсутствие повторяющихся персонажей и ревизию состава.

Ежедневный подарок — 250 Berries один раз на дату UTC. Сброс происходит в 00:00 UTC; время следующего подарка интерфейс показывает в часовом поясе браузера.

## Хранение и локальный профиль

[PGlite](https://pglite.dev/docs/api) запускает PostgreSQL внутри Node.js и сохраняет данные на диск. Drizzle использует обычную PostgreSQL-схему. Каталог данных по умолчанию — .data/postgres; его можно изменить через GAME_DATA_DIR.

Профиль идентифицируется случайным непрозрачным токеном в HttpOnly-cookie. В базе хранится SHA-256 токена. Сессия действует 30 дней и продлевается при открытии приложения. Cookie имеет SameSite=Lax, host-only scope и Secure при HTTPS. Игровые записи находятся в базе, браузер не определяет их содержимое.

Это локальная сессия, а не постоянный облачный аккаунт. При удалении cookie или истечении неактивной сессии создаётся новый профиль; прежние записи в базе не удаляются. Supabase Auth и доступ между устройствами ещё не подключены. Локальные API принимают только loopback-хосты; публикация такой схемы входа в интернете не предусмотрена.

PGlite — вариант для одного локального процесса. Для облака понадобится заменить подключение на управляемый PostgreSQL, подключить проверенную облачную идентичность и перенести данные. SQL, сущности и основные игровые правила уже отделены от UI. Несколько серверных процессов не должны одновременно открывать один локальный каталог PGlite.

## Слои

- src/domain/game.ts: правила экономики, публичные типы и версия пула.
- src/content/cards.ts: 12 изданий и пять персонажей.
- src/db/schema.ts, migrations.ts: таблицы и миграция PostgreSQL.
- src/server/database.ts: инициализация, миграция и регистрация каталога.
- src/server/game-service.ts: операции профиля, боксов, коллекции, команды и наград.
- src/server/http.ts: проверка локального хоста, origin, сессии и входных данных.
- src/features/game: общий клиентский контекст для всех страниц.
- src/features/collection, boxes, crew, profile: отдельные интерфейсы поверх сохранённых данных.

## Надёжность

Кошелёк блокируется в транзакции. Одинаковый ключ открытия возвращает прежний результат; списание, открытие и три экземпляра коммитятся вместе. При ошибке вставки всё откатывается. Отрицательный баланс запрещён ограничением БД.

Владение экземплярами и отсутствие одинаковых персонажей в экипаже защищены сервисом и составными внешними ключами/уникальными ограничениями. Сохранение устаревшей ревизии состава отвергается. Награда за день имеет уникальный источник в журнале кошелька.

Клиент хранит только ключ незавершённого открытия для безопасного повторения запроса. Запросы изменения состояния сериализуются; устаревший фоновый refresh не перезаписывает более новый результат действия. Результат выпадения определяет crypto.randomInt на сервере.

Таблицы с данными игроков имеют RLS, доступ из приложения выполняет серверный владелец БД после проверки сессии. Ответы со снимком профиля имеют Cache-Control private, no-store. Секреты, .data, .env.local и тестовые файлы базы исключены из Git и файловой трассировки сборки.

## API

| Метод | Путь                | Действие                                     |
| ----- | ------------------- | -------------------------------------------- |
| POST  | /api/game/session   | Создать или восстановить локальную сессию    |
| GET   | /api/game/state     | Получить собственный снимок состояния        |
| POST  | /api/game/boxes     | Открыть бокс по requestKey                   |
| POST  | /api/game/favorites | Установить избранное для полученного издания |
| PUT   | /api/game/crew      | Сохранить состав и ожидаемую ревизию         |
| POST  | /api/game/daily     | Получить подарок текущего дня                |
| PATCH | /api/game/profile   | Изменить имя капитана                        |

## Проверка

pnpm test выполняет десять интеграционных проверок, включая одновременные запросы, недостаток средств, rollback, чужие карты, повторяющихся персонажей, устаревшую ревизию, подарок за день и сохранение после закрытия/повторного открытия PostgreSQL. Файловый тест создаёт вложенный каталог с отсутствующими родителями; рабочий .data/postgres не затрагивается.

pnpm test:http выполняет четыре проверки реального HTTP API: cookie и приватность, origin, повтор открытия, списание, подмена цены, подарок и невозможность выбрать другой профиль через тело запроса. Для этих тестов нужен запущенный локальный сервер. Они создают отдельный тестовый профиль.

В браузере проверены стартовая пятёрка, изменение боевой тройки, перестановка персонажей, сохранение после перезагрузки, выдача подарочного бокса, история, избранное и ежедневная награда. Desktop 1440×900 и мобильная компоновка 390×844 проверяются визуально.

## Границы этапа

Облачные аккаунты, PvE, торговля, обмен, продажа дублей и уровни карточек пока не реализованы. Атлас и его журнал остаются отдельным прототипом исследования без наград. Боевые отметки экипажа сохраняются, но бой ещё не запускают.

Следующий игровой этап — одна полноценная активность на Фуше: пошаговый бой 3×3, серверный результат и награда, замыкающие цикл «карты → команда → приключение → новый бокс».
